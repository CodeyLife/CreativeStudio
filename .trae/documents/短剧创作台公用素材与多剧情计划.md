## 摘要

升级独立短剧创作台，引入「短剧创作」容器概念：每个创作台拥有一个**公用参考图片素材库**（图片 + 简短描述），并支持在**同一创作台内创建多个剧情（短剧脚本）**。每部剧情在创建时通过交互手段**手动勾选要引入的公用素材**；被选中的素材会以 `<Subject N>` 参考帧的形式**注入该剧情的生成提示词**（对应 H3 Ref2VA 全参考模式），同时素材图片本身保留为后续视频生成的参考图库。

已确认的决策：
1. 素材用法 = **注入生成提示词 + 参考图库**（选中素材的简短描述+索引注入脚本提示词并映射为 `<Subject N>`；图片供后续 Ref2VA 生成做参考帧）。
2. 容器定位 = **独立创作台**（不依赖小说项目，与现有「独立短剧」一致；`projectId` 仍作为可选的关联作品标记）。

## 目标数据模型

新增迁移 `deploy/postgres/090_short_drama_workspaces_and_materials.sql`：

```sql
-- 短剧创作容器（独立创作台）
CREATE TABLE IF NOT EXISTS short_drama_workspaces (
  id         TEXT PRIMARY KEY,
  title      TEXT NOT NULL,
  description TEXT,
  project_id TEXT REFERENCES novel_projects(id) ON DELETE SET NULL, -- 可选关联，独立创作台默认 NULL
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 公用参考素材（图片 + 简短描述），属于某个创作台，可被该创作台下多部剧情复用
CREATE TABLE IF NOT EXISTS short_drama_materials (
  id           TEXT PRIMARY KEY,
  workspace_id TEXT NOT NULL REFERENCES short_drama_workspaces(id) ON DELETE CASCADE,
  description  TEXT NOT NULL,          -- 简短素材描述
  object_url   TEXT,                   -- 对象存储 key（图片二进制）
  content_hash TEXT NOT NULL,          -- 图片内容 sha256（幂等/去重）
  file_name    TEXT,                   -- 原始文件名
  mime_type    TEXT NOT NULL,
  created_at   TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS idx_sdm_workspace ON short_drama_materials(workspace_id);
CREATE UNIQUE INDEX IF NOT EXISTS ux_sdm_content ON short_drama_materials(workspace_id, content_hash);

-- short_scripts（一部创作台下的一个剧情）新增两列：
--   workspace_id  归属创作台（NULL 保持既有独立剧情兼容）
--   material_refs  该剧情手动选中素材的快照（[ {materialId, objectUrl, description, subjectTag} ]，注入提示词与幂等指纹用）
ALTER TABLE short_scripts ADD COLUMN IF NOT EXISTS workspace_id TEXT REFERENCES short_drama_workspaces(id) ON DELETE SET NULL;
ALTER TABLE short_scripts ADD COLUMN IF NOT EXISTS material_refs JSONB NOT NULL DEFAULT '[]'::jsonb;
CREATE INDEX IF NOT EXISTS idx_short_scripts_workspace ON short_scripts(workspace_id) WHERE workspace_id IS NOT NULL;
```

说明：`material_refs` 存**选中素材快照**（含描述与 `subjectTag`）而非仅 ID，保证生成提示词内容与幂等指纹自包含、不受素材被删/改描述影响。

## 变更清单

### 1. 对象存储二进制支持（`src/novel-v2/object-store.ts`）
- 扩展 `ObjectStoreAdapter`（及 `RuntimeObjectStoreAdapter`、`ContentObjectStore`）新增：
  - `putData(bytes: Buffer, mimeType: string, ext?: string): Promise<ContentObject>`（hash 基于 bytes；`ContentObject` 增加可选的 `mimeType`）。
  - `getData(key: string, mimeType?: string): Promise<Buffer>`。
- `FileContentObjectStore`：`putData` 用 `writeFile(path, bytes)`；`getData` 用 `readFile` 返回 Buffer（不强制 utf8）。
- `S3ContentObjectStore`：`putData` `Body: bytes, ContentType: mimeType`；`getData` `Body.transformToByteArray()` → Buffer。
- 保留 `putText/getText` 供存量文本沿用。

## 假设与决策
- 素材上传走 base64 JSON（与既有 JSON API 一致），图片大小上限 `MATERIAL_MAX_BYTES`（TODO 标注可配置）。
- `material_refs` 采用选中素材**快照**（含描述与 `subjectTag`），保证注入上下文与幂等指纹自包含、删改素材不破坏历史剧情。
- 创作台完全独立于小说项目（决策 2），`project_id` 仅作可选关联标记；既有无 workspace 的剧情与独立创作行为保持兼容（`workspace_id`/`material_refs` 均可空/默认空）。
- 素材注入为**提示词级**（不改变六段结构契约、不升级 `SHORT_SCRIPT_CONTRACT_VERSION`，避免存量产物无谓失效）；仅把素材块作为输入追加，并纳入幂等指纹。选中素材变化触发该剧情重生成（同输入同素材幂等复用）。
