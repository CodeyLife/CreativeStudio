# 短剧双能力计划：章节剧本质量升级 + 核心创意短剧脚本

## Summary

两个目标，均在 MCP 工具层实现：

1. **目标一（章节 → 高质量短剧剧本）**：升级现有 `novel_chapter_script_h3` 管线，把剧作层（开场即冲突、情绪节点节奏、集末卡点、台词密度、伏笔回收、人物经济）纳入生成契约 v5 与提示词，产物为 H3 Ref2VA 六段式 5-10s 分镜提示词（现状已有，做质量升级）。
2. **目标二（核心创意 → 简短短剧脚本）**：新增独立 MCP 工具 `novel_short_script_h3`：输入核心创意（如一个抖音短视频点子），输出同构的 H3 Ref2VA 5-10s 分段分镜提示词，落库 artifact 可幂等复用。

两目标共用同一运行时 skill（h3-video-prompt），通过新增执行点 `short.script` 区分两种创作入口。

## Proposed Changes

### A. 目标一：剧作层纳入 chapter-script 契约 v5

**A1. [chapter-script-h3.ts](../../src/novel-v2/application/chapter-script-h3.ts)**

- `SCRIPT_CONTRACT_VERSION` `"4"` → `"5"`（旧产物按幂等键自动失效重生成）。
- `buildChapterScriptPrompt` 新增一段"剧集剧作契约"（通用叙事模式表述，不嵌题材/角色名）：
  - 首片段在冲突现场开场（3 秒内出钩子形态之一：直接冲突/强悬念/极致反差/身份落差/倒计时压力），前 10 秒呈现核心冲突、对立关系、即时目标；铺垫性开场视为失败。
  - 情绪节点节奏：每 2-4 个片段落一个节点（对话冲突/动作冲突/信息揭示），前 1/3 内完成第一次小反转。
  - 每片段出口是钩子（提问或升压），末片段在冲击瞬间切卡（揭示/接触/决定发生的一刻），不在余韵处收尾。
  - 台词密度：每句承担身份确认/冲突引爆/后果陈述之一；关键情绪节拍静音可读（表情/动作/屏幕文字）。
  - 反转必须有前文呈现过的伏笔（plant → overlook → detonate），正文无伏笔不得加反转。
  - 人物经济：核心三角 + 少量配角，标签+反差+秘密。
- **不加新硬校验**：剧作层属提示层契约（结构不可可靠检测），沿用现有结构校验（标签/时序/对白/节拍覆盖/呈现手段）+ `computeCinematicHints` 提示级模式；根因是"覆盖类问题已在结构层解决，节奏类问题无跨题材可靠结构特征，堆 heuristic 会违反泛化优先"。
- 幂等键不变（内容哈希绑定），仅契约版本号推进。

**A2. [h3-video-prompt.yaml](../../skills/novel-v2/h3-video-prompt.yaml)**：version → 1.3.0；`promptSections["chapter.script"]` 追加剧作层指引段（与 dramaturgy.md 同源压缩版：分段节奏 → 剧集节奏两层表述）。

**A3. 新迁移 `deploy/postgres/049_h3_video_prompt_skill_v1_3.sql`**：upsert h3-video-prompt 运行时 descriptor 至 v1.3.0（含两个执行点 chapter.script + short.script，见 B2），沿用 048 的幂等 upsert 形态。

**A4. 测试 [chapter-script-h3.test.ts](../../src/novel-v2/__tests__/chapter-script-h3.test.ts)**：新增断言——prompt 文本包含剧作契约关键条目（开场即冲突/情绪节点/切卡点/伏笔链）、契约版本为 "5"。

### B. 目标二：新工具 `novel_short_script_h3`（核心创意 → 简短 H3 短剧脚本）

**B1. 新模块 `src/novel-v2/application/short-script-h3.ts`**

- 复用 chapter-script-h3 的导出件：`parseSharedSubjectPreset` / `assembleSegmentPromptText` / `normalizeChapterScriptOutput` / `computeCinematicHints` / 验证器 / `ChapterScript*` 类型（同构六段契约，避免复制）。
- 输入：`{ projectId, idea, instruction?, targetDurationSeconds? }`；`idea` 必填（核心创意描述， minLength 校验 ≥10 字符）；`targetDurationSeconds` 默认 30，clamp 到 10-60。
- 分段预算（题材无关推导）：
  - 片段时长仍 5-10s（复用 `MIN/MAX_SEGMENT_SECONDS`）；
  - `minSegments = max(1, ceil(target/10))`、`maxSegments = min(8, ceil(target/5))`（上限 `MAX_SHORT_SCRIPT_SEGMENTS = 8`）；
  - 校验片段总时长落在 `target ± 10s` 且 ≤ 60s。
- 模型输出 schema：复用 `CHAPTER_SCRIPT_H3_SCHEMA` 结构，但 segments minItems 1 / maxItems 8；`plotBeats` 保留（模型须先穷举创意内的节拍再映射片段——结构化覆盖契约同样适用于原创短剧）。
- prompt（`buildShortScriptPrompt`）：创意输入 + 剧作契约（与 A1 同源，但"改写忠实于正文"边界替换为"忠实于核心创意给定的设定与冲突，不新增与创意冲突的设定"）+ 时长预算 + 人物 appearanceEn 自拟基线。
- 幂等：fingerprint = sha256(projectId + idea + instruction + target + contractVersion)；命中同 fingerprint + contractVersion 的既有 artifact 直接复用。
- 持久化：artifact `kind = "short-script"`、`origin = "short-script-h3"`、`taskId = ${workflowId}:script`；正文组装与 chapter-script 一致。
- 错误契约：沿用 `ChapterScriptSourceError` 模式不新增（输入校验直接 400 语义）。

## Assumptions & Decisions

1. **产物形态**：两目标均输出 H3 Ref2VA 六段式提示词（用户已确认）；人类可读剧本表不在本次范围。
2. **实现位置**：MCP 工具层 + REST 镜像（用户已确认）；前端 UI 面板不做。
3. **`novel_short_script_h3` 必须挂 projectId**：artifacts/幂等/审计都项目作用域，独立创意也归入某项目（可先 `novel_project_create` 建轻量项目）。不做"无项目裸生成"分支，避免两套持久化契约。
4. **版本号取 1.3.0**：v1.2.0 被 045/046（已回滚的章节级定义库抽象）占用过，跨过以免语义混淆。
5. **剧作层不做硬校验**：节奏/钩子类问题无跨题材可靠结构特征，写入 prompt 契约与 skill 指引（版本号推进使旧产物失效重生成），结构层校验维持现状。理由对齐 AGENTS"泛化优先、禁止为通过样本调参"。
6. **契约 v5 与 049 迁移**：A 与 B 共用一条 049 迁移（一次 upsert 到 v1.3.0 双执行点），减少迁移数量。
7. 允许破坏性变更（架构阶段准则）：`SHORT_SCRIPT_*` 常量直接新增，不做兼容层。
