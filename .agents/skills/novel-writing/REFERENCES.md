# 参考资料与来源

> 本文件列出来源与证据分级，说明每类材料的用法和边界。级别：A=作家/编辑/作协公开创作谈；
> B=高校课程/叙事学/故事生成研究；C=指定作品文本细读与跨作品对照；D=开源工具/工作流；
> E=奖项、榜单、传播与改编等成功信号。
> 研究结果只提炼机制与可迁移方法，不复制原句、人物、情节或个别作者的个人文风。

## 证据分级与用法

| 级别 | 证据 | 用法 | 局限 |
| --- | --- | --- | --- |
| A | 作家、编辑、作协媒体的公开创作谈 | 支撑创作者自述的方法与价值取向 | 自述不等于作品全部机制 |
| B | 高校课程、叙事学与故事生成研究 | 支撑概念、结构、视角、人物网络等抽象模型 | 需转化为具体文本证据 |
| C | 指定作品文本细读与跨作品对照 | 提炼"如何实现效果"的机制假设 | 不把单一作品偏好升级为全局规则 |
| D | GitHub 开源工具、工作流、README | 参考数据结构、阶段划分、回归与人机协作 | 必须审查许可证、活跃度、测试、数据边界 |
| E | 茅盾文学奖、网络文学影响力榜、IP/海外传播榜、平台热度 | 选择值得细读的作品池，识别读者承诺与传播机制 | 成功信号不是创作规则，不能替代文本细读 |

## 资料筛选与沉淀标准

1. **来源优先级**：官方奖项/作协专题、作者创作谈、可追溯研究论文、可审查开源项目优先；
   平台热帖、营销稿和读者口碑只能作为待验证线索。
2. **作品入池条件**：至少满足一项可追溯成功信号（重要奖项、长期连载完成、广泛读者影响、
   IP 改编、海外传播、跨圈层讨论），且能抽出具体 craft 机制。
3. **机制提炼格式**：`输入类别 -> 失败类 -> 共享机制 -> 落地执行点 -> 不覆盖边界`。
4. **禁止项**：不把作者声口、角色名、句式、设定名词、章节节拍或平台商业指标写成硬规则；
   不以单本作品替代跨题材验证。
5. **回归要求**：新增规则至少验证原案例与一个不同题材/关系/章节功能样本；生成类改动必须
   看正文、状态变化、事实账本和审校证据，不能只看分数。

## 创作工程化方法

- **雪花法（Snowflake Method）**：Randy Ingermanson《How to Write a Novel Using the
  Snowflake Method》。十步从一句话到场景清单与初稿；核心主张"先设计后写作更快更好"。
  源文章：
  <https://www.advancedfictionwriting.com/articles/snowflake-method/>
- **三幕式 / 三次灾难结构**：经典编剧结构，第一灾=第一幕结束、第二灾=第二幕中点、
  第三灾=第二幕结束逼出第三幕。工程化落地见 METHOD.md §1。
- **Save the Cat / 节拍表**：Blake Snyder 的剧情节拍方法，用于检查节奏与关键时间点；
  是参考框架，不是所有题材的硬契约。
- **场景结构**：Randy Ingermanson《How to Write a Dynamite Scene》——
  场景必须有 POV、目标、冲突与灾难；"没冲突的场景要么加冲突要么删掉"。

## 课程与研究（B 级）

- 《小说写作教程》（高等教育出版社）：人物、故事、情意、素材、背景、场景、视角、
  开篇、推进、结尾、人物塑造与风格。
- 《文学写作》课程大纲（中国社会科学院大学）：视角、人称、叙述参与、情节推进、
  开篇结尾、人物塑造的课程框架。
- **Mapping Out Narrative Structures and Dynamics Using Networks and Textual
  Information**（arXiv:1604.03029）：人物网络、情绪、主题变化作为叙事动态分析对象。
- **Complicating the Social Networks for Better Storytelling**
  （arXiv:2008.10835）：以中国历史文本与历史小说为对象，研究复杂动态人物网络与
  叙事丰富度关系——"更复杂动态的关系网络可增加叙事层次"。
- **Controllable Multi-Character Psychology-Oriented Story Generation**
  （arXiv:2010.05230）：多角色情绪线需要单独建模，不能只给全书一个情绪标签。
- **Strategies for Structuring Story Generation**（arXiv:1902.01109）：
  先规划事件/实体结构再生成表层文本，提升连贯性与多样性。
- **LOT 长文本基准**（arXiv:2108.12960）：长中文文本评估需同时看理解与生成，
  单段流畅度不代表长程能力。
- **WebNovelBench**（arXiv:2505.14818）：网文生成的多维质量评估，可与人类作品和
  不同生成系统比较；LLM-as-Judge 单分数不能当作创作真相。
- **COIG-Writer**（arXiv:2510.14763）：中文创意写作数据强调过程级推理与语言表达共同
  影响质量，可支撑"先给创作过程 scaffolding，再要求成文声部"的分层设计；数据集指标
  仍不能替代真实长篇连续样本。

## 作品细读案例（C 级，机制参考）

| 作品 | 观察点 | 反面样本 |
| --- | --- | --- |
| 《平凡的世界》 | 现实逻辑约束人物资源/机会/阶层/选择；群像共同时代变化 | 不要求所有作品写实/百万字 |
| 《人世间》 | 家庭、单位、城市变迁和公共时代共同塑造人物命运；长期亲情/责任有代际后果 | 不把年代跨度、苦难密度或主旋律表达当质量 |
| 《活着》 | POV、人物知识、语言互相匹配；苦难重量来自如何继续生活 | 不把悲剧/第一人称做成通用模板 |
| 《许三观卖血记》 | 重复行动每次改变家庭关系、尊严边界和生活处境，形成递进而非循环 | 不把重复事件当可复制节拍 |
| 《三体》 | 设定先形成规则与推演空间，宏观后果压回人物与社会选择 | 不奖励更大尺度/更多术语/更冷酷结论 |
| 《我们生活在南京》 | 末日科幻可用通信限制、时间错位和日常物件建立亲密感与悬念 | 不把双时空通信或末日设定当模板 |
| 《长安的荔枝》 | 把宏大事件拆成连续技术/地理/制度/人际障碍 | 不把考据数量/倒计时当故事质量 |
| 《繁花》 | 城市语言、饭局/生意/流言网络承载人物关系和时代气味 | 不把方言密度或碎片叙述当高级感 |
| 《诡秘之主》 | 连载需要可持续读者问题、阶段回报、长期谜团；现实质感承托超现实 | 热度/榜单只证明参与度，不证明每节都优秀 |
| 《全职高手》 | 职业系统、团队协作、旧身份/新起点和竞技过程共同制造爽感 | 不把比赛流程、职业标签或粉丝热度当通用答案 |
| 《道诡异仙》 | 不可靠感知、身份裂缝和世界规则互相污染，形成持续认知压力 | 不把混乱、痛苦或猎奇升级成目标本身 |
| 《雪中悍刀行》 | 江湖与庙堂相互影响、配角独立弧光、武戏承载身份与价值冲突 | 后期战力膨胀、支线拖长、收束压力 |
| 《剑来》 | 庞大世界、文化思想、人物声口、意象复现、慢热节奏 | 过度哲思、叙事停滞、重复说明、记忆负担 |
| 《天之下》 | 多势力、多地域、多人物的政治/江湖网络，靠选择代价而非单人升级推进 | 不把势力数量、设定厚度或慢铺垫当质量 |

对多部作品的共同结论不是"组合几种作者风格"，而是：人物选择产生剧情，剧情改变关系
和认知，世界规则制造真实代价，语言把一切转化为可感经验；长篇通过伏笔、意象、回声和
状态账本保持跨章节的意义累积。

### 跨作品机制归纳

| 机制 | 正向信号 | 常见失效 | 落地执行点 |
| --- | --- | --- | --- |
| 读者承诺 | 读者知道持续阅读会得到哪类体验，且阶段性兑现 | 只有题材标签、设定噱头或"会很好看" | 创作契约、分卷承诺、章节回报 |
| 人物选择 | 人物欲望遇到真实阻力，选择带来代价和新局面 | 事件推动人物，人物只解释心情 | 人物卡、场景五问、审校证据 |
| 世界压力 | 规则、制度、资源、文化会改变可选集合 | 设定只用于说明、装饰或临时救场 | 世界观规则表、事实账本、蓝图约束 |
| 群像网络 | 配角有独立目标，关系会随事件重排 | 配角只供主角打脸、解释或牺牲 | 人物关系账本、POV 分配、弧交汇点 |
| 长线回报 | 伏笔、谜团、意象和承诺有记录、变化与兑现 | 悬念堆积、忘线、机械反转 | 伏笔/承诺账本、章节状态变更 |
| 声音与质感 | 叙述语言来自 POV 的知识、阶层、情绪和处境 | 通用"网文腔"/"文学腔"覆盖所有角色 | POV 声部检查、句法修订 |

## 开源工具与工作流（D 级）

- **hestudy/snowflake-fiction**：把创意、人物、场景、写作、质量复核拆成可调用步骤；
  雪花法/黄金三章/字数和爽点密度不能作为所有题材的硬契约。
- **forsonny/book-os**：将 Standards、Novel、Manuscripts 分成不同上下文层；
  轻量摘要不能替代事实真源和截止点过滤。
- **NousResearch/autonovel**：foundation → draft → revision → full-manuscript review，
  维护 canon，允许传播债务；README 中的模型/分数/生产结果不是质量证明。
- **StoryWriter**（arXiv:2506.16445）：事件关系、章节级规划、按当前事件压缩历史。
- **EdwardAThomson/NovelWriter**：世界/结构/场景/章节/多级审校的 agent 化编排。
- **MangoLion/plotbunni**：Act → Chapter → Scene 层级、概念缓存、场景关联、本地数据。
- **dylanhogg/gptauthor**：作者先提供故事描述，生成 synopsis 经人工审核后按章生成——
  作者审核点应位于大纲与正文之间。
- **github/spec-kit Fiction Book Writing**：outline 作为作者权威检查点，要求因果 beat、
  want/get、对白潜台词、感官锚点、主题交付和 POV 信息地图。
- **lsg1103275794/novel-writer-style-cn**：把中文词汇、句法、叙事、描写、节奏分析与
  情节/时间线/角色一致性结合；量化风格指标不能代替文学判断。

## 使用规则

1. 外部资料只提出可检验的机制假设，不直接变成某部作品的禁用词或章节模板。
2. 每条机制至少落到：创作契约、章节/场景结构、审校维度、回归测试中的一层；只写
   "原则"不落结构不算闭环。
3. 需要新增规则时，先写受影响输入类别与不覆盖边界，再补原失败样本与跨题材反例。
4. 对在世作者，优先学习可解释的技法，不生成高度可识别的个人风格复制品。
5. 任何来自外部项目的提示词、范文、训练数据或源码，进入作品前做许可证与来源审核。
